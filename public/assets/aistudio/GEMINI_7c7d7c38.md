```
## Project: TypeTrack
```

```
TypeTrack is a modern web-based typing application designed to help beginners
build typing confidence, improve typing speed, and develop accuracy through
consistent practice.
```

```
The application should feel like a supportive typing coach, not a boring
typing test.
```

# `# 1. Core Product Vision` 

```
Build TypeTrack around this idea:
```

```
> "Practice calmly. Build confidence. Get faster over time."
```

```
TypeTrack should help a beginner progress from:
```

- `Learning basic typing` 

- `Becoming comfortable with the keyboard` 

- `Improving accuracy` 

- `Increasing typing speed` 

- `Building consistent practice habits` 

- `Tracking long-term improvement` 

```
The experience should encourage improvement rather than make beginners feel
bad about slow typing speeds.
```

# `# 2. Target User` 

```
Primary users are beginners who:
```

- `Are learning touch typing` 

- `Have low or inconsistent typing speed` 

- `Want to improve gradually` 

- `May feel nervous about typing tests` 

- `Need clear guidance` 

- `Want to see their progress over time` 

```
The UI and language should be friendly and encouraging.
```

```
Avoid making the user feel like they are being judged.
```

- `# 3. Product Principles` 

```
Always prioritize:
```

`1. Simplicity` 

`2. Clarity` 

`3. Encouragement` 

`4. Accessibility` 

`5. Consistent progress` 

`6. Peaceful focus` 

`7. Meaningful feedback` 

`8. Attractive modern UI` 

```
Do not overload the user with unnecessary information.
```

```
# 4. UI/UX Direction
```

```
TypeTrack must NOT look like a generic AI-generated dashboard.
```

```
Avoid:
```

- `Excessive gradients` 

- `Random glassmorphism` 

- `Too many cards` 

- `Excessive rounded containers` 

- `Huge headings everywhere` 

- `Unnecessary animations` 

- `Generic purple AI aesthetics` 

- `Visual clutter` 

- `Excessive icons` 

- `Fake complexity` 

```
The interface should feel intentionally designed.
```

```
Aim for:
```

```
- Modern
- Calm
- Premium
- Friendly
- Focused
- Human
```

- `Interactive` 

```
Use generous whitespace and strong visual hierarchy.
```

```
# 5. TypeTrack Brand
```

```
Product name:
```

```
TypeTrack
```

```
Brand concept:
```

```
A calm companion that tracks typing improvement over time.
```

```
Logo concept:
```

```
Create a minimal TypeTrack wordmark combined with a subtle typing/cursor
```

```
Possible visual ideas:
```

```
- Typing rhythm
```


```
# 6. Color System
```

```
Use a calm and focused visual system.
```

```
Preferred direction:
```

- `Soft neutral background` 

- `Strong readable primary text` 

- `One primary accent color` 

- `One secondary accent` 

- `Subtle success state` 

- `Subtle error state` 

```
Avoid extremely saturated colors.
Errors should not feel aggressive.
Success should feel rewarding but subtle.
Maintain sufficient contrast for accessibility.
```

```
# 7. Typography
```

```
Use a clean modern sans-serif font.
```

```
Typography should prioritize:
```

- `Readability` 

- `Comfortable line height` 

- `Clear hierarchy` 

- `Excellent readability during typing` 

```
The typing text itself should be large and comfortable to read.
Avoid decorative fonts for the main typing experience.
```

```
# 8. Main Typing Experience
```

```
The typing screen is the most important screen.
```

```
It should contain:
```

- `Current typing text` 

- `Character/word highlighting` 

- `Typing cursor` 

- `WPM` 

- `Accuracy` 

- `Timer` 

- `Progress` 

- `Pause` 

- `Restart` 

- `Difficulty` 

- `Text/category selection` 

```
The typing area should receive the majority of the user's visual attention.
Minimize distractions while the user is typing.
```

```
# 9. Typing Feedback
```

```
Provide immediate but calm feedback.
```

```
Correct typing:
- Smooth progress
- Subtle positive feedback
```

```
Incorrect typing:
- Clearly identify the mistake
```

- `Avoid harsh animations` 

- `Avoid embarrassing messages` 

- `Allow the user to recover easily` 

```
The interface should communicate:
```

```
> "Keep going. You are improving."
rather than:
> "You failed."
```

```
# 10. Beginner Guidance
TypeTrack should actively help beginners.
```

```
Include guidance such as:
```

- `Home-row introduction` 

- `Finger-position guidance` 

- `Beginner exercises` 

- `Easy words` 

- `Common letter combinations` 

- `Gradually increasing difficulty` 

```
Do not introduce advanced exercises too quickly.
```

```
Progression should feel natural.
```

```
# 11. Learning Levels
```

```
Create a progression system such as:
```

```
Level 1  Keyboard Basics
Level 2  Home Row
Level 3  Common Letters
Level 4  Words
Level 5  Sentences
Level 6  Accuracy
Level 7  Speed
Level 8  Advanced Practice
```

```
Users should unlock or progress through exercises based on practice,
not simply speed.
```

```
Accuracy should matter alongside speed.
```

```
# 12. Progress Tracking
```

```
Track meaningful metrics:
```

- `WPM` 

- `Accuracy` 

- `Practice time` 

- `Sessions completed` 

- `Best WPM` 

- `Average WPM` 

- `Accuracy trend` 

- `Words typed` 

- `Improvement over time` 

```
Show progress visually using simple charts and useful insights.
Example:
```

```
"Your accuracy improved by 4% this week."
```

```
Avoid overwhelming dashboards.
```

```
# 13. Dashboard
```

```
The dashboard should immediately answer:
```

- `How am I doing?` 

- `What did I practice?` 

- `Am I improving?` 

- `What should I practice next?` 

```
Possible sections:
```

- `Today's practice` 

- `Current WPM` 

- `Accuracy` 

- `Weekly progress` 

- `Recent sessions` 

- `Recommended exercise` 

- `Practice streak` 

```
Keep the dashboard focused.
```

```
# 14. Gamification
```

```
Use gentle gamification.
```

```
Good examples:
```

- `Practice streaks` 

- `Levels` 

- `Milestones` 

- `Personal records` 

- `Progress badges` 

- `Daily goals` 

```
Avoid aggressive leaderboards or systems that make beginners feel inferior.
The primary goal is personal improvement.
```

```
# 15. Interactive Design
```

```
Interactions should feel responsive and intentional.
```

```
Use:
```

- `Smooth hover states` 

- `Keyboard shortcuts` 

- `Subtle transitions` 

- `Animated progress` 

- `Interactive charts` 

- `Theme switching` 

- `Difficulty selection` 

- `Practice recommendations` 

```
Animations should support the experience, not distract from typing.
```

```
Prefer short, subtle transitions.
```

```
# 16. Peaceful Typing Mode
```

```
Provide a dedicated focus mode.
```

```
When enabled:
```

- `Hide unnecessary navigation` 

- `Reduce visual distractions` 

- `Increase typing-area size` 

- `Keep only essential metrics` 

- `Use subtle animations` 

- `Maintain comfortable spacing` 

```
The user should feel like they have entered a quiet digital workspace.
```

```
# 17. Results Screen
```

```
After a typing session, show:
```

- `WPM` 

- `Accuracy` 

- `Errors` 

- `Time` 

- `Words typed` 

- `Personal best comparison` 

- `Progress compared with previous sessions` 

```
Then provide:
```

- `Practice Again` 

- `Try Recommended Exercise` 

- `View Progress` 

- `Return to Dashboard` 

```
Keep the tone encouraging.
```

```
# 18. Responsive Design
```

```
TypeTrack must work well on:
```

```
- Desktop
```

- `Laptop` 

- `Tablet` 

```
- Mobile
Desktop should provide the best typing experience.
On smaller screens:
```

- `Maintain readable text` 

- `Avoid horizontal scrolling` 

- `Simplify navigation` 

- `Preserve essential metrics` 

```
- Keep controls touch-friendly
---
# 19. Accessibility
Follow accessibility best practices.
Ensure:
```

- `Good color contrast` 

- `Keyboard navigation` 

- `Visible focus states` 

- `Semantic HTML` 

- `Accessible buttons` 

- `Screen-reader-friendly labels` 

- `Reduced-motion support` 

```
Never rely only on color to communicate success or errors.
```

- `# 20. Technical Development Rules Before implementing a feature:` 

`1. Understand the existing project structure.` 

`2. Reuse existing components when appropriate.` 

`3. Avoid unnecessary dependencies.` 

`4. Keep components modular.` 

`5. Keep business logic separate from UI.` 

`6. Write readable code.` 

`7. Handle loading and error states.` 

`8. Test important interactions.` 

`9. Do not break existing functionality.` 

`10. Prefer simple solutions over unnecessary abstraction. ---` 

```
# 21. AI Coding Agent Rules
When working on TypeTrack:
```

- `Inspect relevant files before making changes.` 

- `Do not blindly rewrite existing components.` 

- `Understand the current design system before creating new UI.` 

- `Reuse existing components and styles when possible.` 

- `Keep the UI consistent across pages.` 

- `Do not introduce a new library without a clear reason.` 

- `Do not change unrelated code.` 

- `Test changes after implementation.` 

- `Fix errors before considering a task complete.` 

```
When requirements are ambiguous, prefer the simplest implementation consistent
with the product vision.
```

- `# 22. Design Quality Check` 

```
Before completing any UI task, ask:
```

- `Does this look intentionally designed?` 

- `Is the interface easy for a beginner?` 

- `Is the main action obvious?` 

- `Is there unnecessary visual clutter?` 

- `Does the design feel calm?` 

- `Does the UI encourage the user?` 

- `Does it look consistent with TypeTrack?` 

- `Does it work on mobile?` 

- `Are animations subtle?` 

- `Does it avoid generic AI-generated UI patterns?` 

- `# 23. Definition of Done` 

- `A feature is not complete until:` 

- `It works correctly.` 

- `It matches the TypeTrack design language.` 

- `It is responsive.` 

- `It is accessible.` 

- `It handles errors gracefully.` 

- `Existing functionality still works.` 

- `The UI feels polished.` 

- `The experience remains simple for beginners.` 

```

```

```
TypeTrack should feel like:
```

```
A patient typing coach.
```

```
Not:
```

- `A strict teacher` 

- `A competitive leaderboard` 

- `A corporate dashboard` 

- `A generic AI application` 

- `A boring typing test`
